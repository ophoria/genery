# Network access and authorization

Local control remains on the loopback HTTP listener (3001); development Vite also binds only loopback. LAN access uses a separate listener (3002), accepts only private-network peers, and can require account login or allow an explicitly configured guest role and directory grants. Internet access uses a separate TLS listener (3443), a configured public HTTPS origin, and mandatory account login. Forwarded headers never confer local privileges. Passworded LAN connections also use TLS. Certificates are configured locally, with private keys never returned through the API.

Accounts are admin, moderator, or normal. Only an authenticated admin connecting over the local listener or private LAN can manage users. Network settings require local control. Admins retain gallery functionality. Moderators may change metadata, analyze, copy, rename, and archive authorized images, but cannot delete files or replace existing files. Normal users can only browse, scan, read metadata/results, search, filter, and view images. Moderators can install supported AI models into app-managed storage and save personal AI settings; global settings remain administrator-managed. Restricted accounts can inspect and cancel only their own AI jobs.

Each restricted account has one or more canonical directory grants, each with an explicit recursive flag. All API paths, scan results, metadata exports/imports, AI results/jobs, operation sources and destinations must remain inside grants. Reject symlinks in restricted paths and revalidate before filesystem use. Rename/archive names must be single basenames. Deny unknown routes by default. Reject non-image raw file reads. No public caching of private images; SVG downloads use attachment/sandbox controls.

Passwords use salted scrypt; account files are private and atomically replaced. Sessions use random opaque cookies, HttpOnly, SameSite=Strict, Secure on TLS, idle/absolute expiration, and server-side revocation on account/config changes. Login attempts are bounded and rate limited. Same-origin checks and JSON-only mutations prevent CSRF. Host checks prevent DNS rebinding. Tests exercise permissions through direct HTTP calls, malformed inputs, symlinks, sibling-prefix paths, rename/archive traversal, user administration from internet, session revocation, guest policy, and listener transitions.

Completion requires implemented settings/account/login UI, live listener behavior, role-aware controls and scoped folder navigation, full backend adversarial tests, build/regression tests, and runtime verification. TLS certificates and router port forwarding are deployment prerequisites, not automatically generated public credentials.
